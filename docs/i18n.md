# Internationalization

The application uses [`next-intl`](https://next-intl.dev/) with three locales:

- `ru` — Russian (default)
- `uz` — Uzbek
- `en` — English

## Architecture

Locale selection is stored in the first-party `NEXT_LOCALE` cookie. The app keeps
its existing URLs (`/dashboard`, `/candidates`, OAuth callbacks, and API routes)
instead of adding a `[locale]` route segment. This is intentional for an
authenticated ATS: switching the interface language should not change entity
URLs or integration callback paths.

Key files:

- `src/i18n/config.ts` — supported locales, default locale, and cookie name
- `src/i18n/request.ts` — request locale resolution and message loading
- `src/types/i18n.d.ts` — typed `next-intl` locale and message augmentation
- `src/app/_components/locale-switcher.tsx` — language selector
- `messages/ru.json`, `messages/uz.json`, `messages/en.json` — message catalogs

`src/app/layout.tsx` resolves the locale on the server, sets the `<html lang>`
attribute, and provides messages to client components. Dates and numbers use
`next-intl` formatters so their separators and ordering follow the selected
locale.

The selected locale is also sent to integrations that expose localized
reference data. For example, the PersonHunters dictionaries query uses the
active `ru`, `uz`, or `en` locale.

## Adding interface copy

Add the same key to all three JSON catalogs. Russian is the source catalog used
for TypeScript key inference, while a catalog-alignment check should ensure that
Uzbek and English contain exactly the same key paths.

Client component:

```tsx
import { useTranslations } from "next-intl";

const t = useTranslations("Candidates");
return <h1>{t("title")}</h1>;
```

Server component:

```tsx
import { getTranslations } from "next-intl/server";

const t = await getTranslations("Candidates");
return <h1>{t("title")}</h1>;
```

For lookup tables, keep stable values in the database and translate only their
display labels through `src/i18n/use-localized-lookups.ts`. User-authored text,
résumé content, vacancy descriptions, and historical activity prose remain in
the language in which they were stored.

## Verification

Run:

```sh
bun run i18n:check
bun run check
bun run typecheck
SKIP_ENV_VALIDATION=1 bun run build
```

`bun run i18n:check` compares the flattened key sets of all three catalogs.
Every locale must contain the same keys.
